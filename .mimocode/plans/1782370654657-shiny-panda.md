# Plan: Fix Root .htaccess — URLs Without `/` and Without `.php`

## Problem
The root `.htaccess` currently has rules 2a and 2b that **add trailing slashes** when stripping `.php`:
- `/foo.php/` → redirects to `/foo/` (wrong — user wants `/foo`)
- `/foo.php` → redirects to `/foo/` (wrong — user wants `/foo`)

Also, URLs with trailing slash like `/foo/` have no rule to strip the slash and serve `foo.php`.

## Goal
Main website URLs should work as:
| Input | Behavior |
|---|---|
| `/foo.php` | 301 → `/foo` |
| `/foo.php/` | 301 → `/foo` |
| `/foo/` | 301 → `/foo` |
| `/foo` | Serves `foo.php` internally |

Blog folder (`/blog/`) is excluded from all main rules — blog has its own `.htaccess`.

## Changes — Only Root `.htaccess`

**File:** `/Users/bp/Desktop/Website With Git/RF- Update/.htaccess`

1. **Rule 2a** — Fix `/(.+)/\.php/?` pattern: redirect to `$1` instead of `$1/` (remove trailing slash). Also add `!^/blog/` exclusion.
2. **Rule 2b** — Fix `/([^.]+)\.php/?` pattern: redirect to `/$1` instead of `/$1/` (remove trailing slash). Also add `!^/blog/` exclusion.
3. **Add new rule** — Strip trailing slash from extensionless URLs: `/foo/` → 301 → `/foo` (for non-blog, non-file, non-directory URLs).
4. Keep all legacy redirects and the extensionless rewrite rule (section 3) as-is.

**DO NOT** touch `/Users/bp/Desktop/Website With Git/RF- Update/blog/.htaccess`.
